# Исправление обработки пустых ответов API

## Проблема

При удалении отделов и пользователей возникала ошибка:
```
Failed to execute 'json' on 'Response': Unexpected end of JSON input
```

**Причина:** Бэкенд возвращает пустой ответ (204 No Content или пустое тело), а фронтенд пытался распарсить его как JSON.

## Решение

Обновлена функция `request` в API модулях для корректной обработки пустых ответов.

### Было:
```typescript
async function request<T>(path: string, options: RequestInit): Promise<T> {
  // ... fetch logic ...
  
  if (!res.ok) {
    // error handling
  }
  
  return res.json(); // ❌ Ошибка при пустом ответе
}
```

### Стало:
```typescript
async function request<T>(path: string, options: RequestInit): Promise<T> {
  // ... fetch logic ...
  
  if (!res.ok) {
    // error handling
  }
  
  // ✅ Handle empty response (204 No Content or empty body)
  if (res.status === 204 || res.headers.get('content-length') === '0') {
    return undefined as T;
  }
  
  const text = await res.text();
  if (!text) {
    return undefined as T;
  }
  
  try {
    return JSON.parse(text);
  } catch {
    return text as unknown as T;
  }
}
```

## Преимущества нового подхода

1. **Обработка 204 No Content** - корректная обработка статуса 204
2. **Проверка content-length** - проверка заголовка для пустого тела
3. **Безопасный парсинг** - попытка парсинга с обработкой ошибок
4. **Fallback на текст** - если не JSON, возвращается текст

- Могут вернуть пустой ответ
- Возвращают 204 No Content
